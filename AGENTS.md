# AGENTS.md

AI-driven MIRI drug discovery research pipeline: drug SMILES → HG (biological) + UniMol (3D) embeddings → XPert DEG prediction (978 L1000 landmark genes) → MIRI efficacy ranking. Research codebase, not a conventional software project.

## Docs convention

- `AGENTS.md` is the only agent doc, kept at this root (routing index) and in `pert_model/xpert/`, `drug_emb_model/hg/`, each `workflow/xpert-fda-miri-v*` (v1/v1.1/v2/v3), and `pert_data/`. Read the subdir `AGENTS.md` before touching code/data there. `pert_data/` is fully gitignored (on-disk only, not tracked) since 2026-08-12 — its `AGENTS.md` lives on disk but is not version-controlled.
- Update any `AGENTS.md` you loaded at session end. No `CLAUDE.md`/`README.md` exist.

## Layout

- `pert_data/` — CM drug-perturbation data lake (see `pert_data/AGENTS.md`): `dtoxs_primary/` (DToxS primary: the released LINCS LDS-1593 well-level package `Data/`/`Metadata/`/…, plus `v1-frozen/` — the byte-identical v1-era package; v1's frozen finetune `dtoxs.h5ad` moved into the v1 workflow step 03 on 2026-08-28; the GSE146095/GSE146096 raw GEO deposit deleted 2026-08-18), `dtoxs_ipsc/`, `gse244740/`, `gse262419/`, `gse247541/`, and `xpert-l1000/` (XPert pretrain h5ads; the older `l1000-xpert/` name is a fallback in the code). `dtoxs-xpert/` and the `cm/` grouping removed 2026-08-17 (ADR 0011); GSE221595 removed 2026-08-12 (user decision). `pert_model/new-model/` — design docs, **not implemented**; don't build on it.
- `drug_emb_model/hg/` — HeteroGNN drug embedding model (**pure code library**, ADR 0008): `src/` + `run.sh` + `run.ipynb` only. Its author HG reference now lives in the workflow `input/`; the orphaned FDA-extension data/weights are archived at `reference/hg-fda-extension-archive/` (gitignored).
- `pert_model/xpert/` — XPert drug perturbation prediction model (pure library: `src/`, `metadata/`, `metrics/`, `reproducing/`, pretrain `run.sh`). The pretrain weight + YAML live in the workflows (`04_xpert_pretrain/`); `cm` is an additive dataset name (union-CM finetune, treated like `dtoxs`).
- `workflow/xpert-fda-miri-v1/` — the **canonical finalized MIRI screening workflow** (docs/adr/0007): author-aligned, L1000-contained FDA screen (1,004 drugs, `drug_idx < 8981`), 11 steps `01_drug_embed`…`11_integrate` (identical layout to v1.1/v2/v3), workflow-owned `input/` (incl. author HG reference + precomputed UniMol array) and pretrain/finetune YAMLs, authoritative Entrez-verified DToxS→L1000 gene map (`_lib/gene_mapping.py`, `_lib/verify_genes.py`). Frozen DToxS-only finetune data is workflow-owned in step 03 (`03_cm_finetune_data/output/dtoxs.h5ad`, moved from `pert_data/dtoxs_primary/v1-frozen/`; its fold columns are regenerated in place under the unified fold scheme, ADR 0014). The agentic bilingual report is archived as a non-numbered `report/` stage.
- `workflow/xpert-fda-miri-v2/` — **union-CM finetune sibling** of v1 (docs/adr/0009 + 0015): the same author-aligned 1,004-drug screen, but the XPert finetune (steps 05/06) trains on the workflow-built union h5ad (step `03_cm_finetune_data`). Since docs/adr/0015 the finetune scope is **primary + iPSC only** (`dtoxs_primary` 662 + `dtoxs_ipsc` 296 = 958 rows), each preprocessed independently (978 landmarks → CPM → log2 → **per-`(dataset, plate)` QN** to the L1000 pretrain → **per-plate matched control** (ADR 0016) → author dose bins from **real µM concentrations** — paper Table 1 KIs / GSE217423 series-matrix shared non-KIs / literature Cmax with citations for primary-only drugs) with a single-cell encoding (`cell_iname="cardiomyocyte"`, `cell_idx=0`) at v1's 24 h slot. The benchmark test sets are **byte-identical to v1.1's** — step 05 imports v1.1's fold columns verbatim for primary rows (matched by well id) and assigns iPSC rows per the isolation rules (warm-start all-train; cold-drug test drugs excluded from both datasets' train), plus the L1000-pretrain zero-shot column. The delta report vs v1.1 (`finetune_delta.md`) audits the primary arm's dose/cell-name + per-plate changes. gse244740/gse262419/gse247541 are no longer extracted in the build (the standalone drug-overlap report still audits all five). **11 steps `01_drug_embed`…`11_integrate`** (the agentic report was removed per spec 1; v1's report is archived as a non-numbered `report/` stage); v1-identical except the finetune data + the step-03 composition report. Screen predicts at dose_idx 0 / time_idx 2 (v1 exposure).
- `workflow/xpert-fda-miri-v1.1/` — **DToxS-LINCS testbed** (docs/adr/0012): an 11-step mirror of v1 (same 11-step layout as v2) whose only change is the finetune data: step `03_cm_finetune_data` rebuilds the DToxS finetune h5ad (662 samples / 45 drugs) from the LINCS LDS-1593 wells, **per-plate normalized** (ADR 0016), schema-parity-gated vs v1's frozen `workflow/xpert-fda-miri-v1/03_cm_finetune_data/output/dtoxs.h5ad` with an auditable delta report (incl. the per-plate deviation). v1.1 validated the fresh build + the 11-step renumbering before v1 adopted the same layout. Benchmarks the unified warm-start + cold-drug folds (ADR 0014; fold columns X-independent, byte-stable across the per-plate rebuild). No agentic report step.
- `workflow/xpert-fda-miri-v3/` — **all-CM finetune sibling** of v1 (docs/adr/0017): the same author-aligned 1,004-drug screen, 11 steps `01_drug_embed`…`11_integrate` (no agentic report; v1's report is archived as a non-numbered `report/` stage), whose XPert finetune (steps 05/06) trains on the workflow-built union of **all four usable CM datasets** (`dtoxs_primary` 662 + `dtoxs_ipsc` 296 + `gse244740` ~2,424 + `gse262419` ~936 = ~4,318 rows), each per-plate normalized (ADR 0016) with real-concentration dose bins. gse247541 is excluded (6-day exposure, 2 in-HG drugs). The benchmark test sets are **byte-identical to v2's** (primary rows import v1.1's folds verbatim); gse244740/gse262419 rows are **train-only** (cold-drug fold test drugs excluded from all four datasets' train). gse244740, not gse262419, dominates the union (~56% of rows). Screen predicts at dose_idx 0 / time_idx 2. Step 05 hosts two benchmark methods (ADR 0018): the official **dtoxs-primary bench** (`dtoxs-primary/`, test sets all primary-arm) and the **data-ablation bench** (`data-ablation/`, 3 seeds × warm-start/cold-drug × 5 train-size fractions on per-seed unified test sets).
- `workflow/xpert-fda-miri-v0/` — frozen legacy pipeline snapshot (gitignored; sole historical reference).
- `workflow/xpert-bench-v1.html` — cross-workflow benchmark comparison page (v1/v1.1/v2/v3 side by side), hand-edited (no generator script); links each workflow's own bench plot (v1/v1.1/v2 `benchmark.png`; v3 `dtoxs-primary/dtoxs-primary-bench.png`), never embeds/regenerates images. The v3 fold bench moved to `dtoxs-primary/` and its plot was renamed `dtoxs-primary-bench.png` since its fold test sets all come from the dtoxs_primary arm (ADR 0018).
- `disease_data/miri/{GSE}/` — shared per-GSE disease inputs (raw data + DEG lists).
- `reference/` — literature PDFs + the gitignored `hg-fda-extension-archive/`; background reading. `reference/pert_data/` holds the CM dataset papers (PDF + extracted markdown + `publications.md`).
- The pre-ADR-0007 v1/v2/v3 MIRI workflow variants exist only in git history.

## Domain glossary

- **author reference** — the L1000 HG embeddings (rows 0–8980) that the author-given XPert was pretrained on, workflow-owned at `workflow/xpert-fda-miri-v1/input/HG_drug_embeddings.npy`, byte-identical to the article's figshare release. The HG *model* that produced it was never released.
- **FDA extension** — the 2,123 FDA drugs (rows 8981–11103) and their graph inputs; only used by the removed v1/v2 variants. Preserved for provenance in `reference/hg-fda-extension-archive/`.
- **author-pinned inference** — the removed v2 step-02 frozen layer-by-layer forward over the extended graph (docs/adr/0006, superseded).
- **norm mapping** — the removed v1's undocumented scale-patching of FDA rows to the author scale (superseded by ADR 0007).
- **parity** — the finalized screen's constraint that step-01 HG output is byte-identical to the author reference (`np.array_equal`), and that the refactored workflow reproduces v3's outputs.
- **pretrain unit** — the workflow-owned XPert pretrain weight + `l1000.yaml` (`04_xpert_pretrain/` in all of v1/v1.1/v2/v3); the L1000 pretrain h5ads live in `pert_data/l1000-xpert/data/`.

## Environment

- Single conda env **`arc`** (Python 3.13) for all subprojects; every `run.sh` calls `conda activate arc`. Created from root `environment.yml` (see `docs/adr/0003`). On this machine it exists as a rename of the legacy `xpert` env (full stack incl. torch+CUDA; R packages for `disease_data/miri/` may be incomplete — install from `environment.yml` if ortholog remapping is needed).
- Subprojects exchange data only via pre-computed files (`.npy`, `.csv`, `.h5ad`); no shared runtime.

- `drug_emb_model/hg/` — `bash run.sh` (pretrain; needs the archived `data/` restored from `reference/hg-fda-extension-archive/`). Dormant library.

CLI: `python <step>/<script>.py`. GPU steps 05/06/07; archived agentic report under `report/` (external biomni backend).

## Data facts and gotchas

- The finalized MIRI screen covers 1,004 L1000-contained FDA drugs (`drug_idx < 8981`); the FDA-extension rows (8981–11103) are out of scope and never predicted.
- The author HG model that produced the author reference was never released (figshare ships only XPert checkpoints + the HG embedding). The archived HG checkpoint (`reference/hg-fda-extension-archive/model/20260518_102121/`) reproduces its own phase1 reference, not the author reference.
- Both L1000 and the CM datasets are log2 expression space — no z-score conversion in training. The ranking pipeline z-scores the predicted DEG (workflow step 07); always use it.
- The workflow's predict indexes the precomputed UniMol array by drug index — do not regenerate UniMol features from SMILES at predict time (feature drift).
- Known limitation: XPert predicts ~97.2% down-regulated DEGs with very low inter-drug variance, hurting downstream discrimination.
- Large artifacts (`.npy`, `.pth`, `.csv`, `.h5ad`, `.pdf`) and `.env` are gitignored — never commit them. Pipeline CSVs/PNGs are regenerated outputs.
- No lint/test/typecheck/CI; verification is via gates and manual output inspection. Do not invent test commands.
