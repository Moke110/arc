HG & XPert Training: 4 Flowcharts

Two models, four training stages, two eras. This lesson gives you a map you can redraw from memory — what each stage eats, what it optimizes, what it spits out, and how v0 (legacy, library-driven) and v1 (step-wise workflow) orchestrate the same training.

Every flowchart uses the notation [category]label with + for parallel inputs and -> for a transformation (training run, data collection, or inference). Everything below is verified against the codebase — file paths and line numbers are cited.

0. The big picture

Drug embeddings come first, then the DEG predictor. The HG graph model makes biological drug embeddings; XPert turns those embeddings + chemistry + cell state into predicted gene-expression perturbations.

[model]HG_l1000 -> [embs]all_drugs_idx2HG.npy (11,104×256)
                                   |
                                   v
[model]XPert_l1000 + [data]DToxS -> [model]XPert_dtoxs -> [output]xpert_fda-cm_deg.csv

1. HG pretrain (L1000, 8,981 drugs)

Source: drug_emb_model/hg/src/pretrain_hg.py; launcher drug_emb_model/hg/run.sh.

[drug nodes]all_drug_node_feat_8981.npy (512d)
+ [gene nodes]all_gene_node_feat_19392.npy (512d)
+ [edges]PPI 901,260 gene-gene (STRING>700, weighted)
+ [edges]DTI 12,890 drug-gene
+ [edges]DDS 287,834 drug-drug (Tanimoto)
+ [model]HeteroGNN_untrained  (3×SAGEConv, 512→256, ReLU)
-> [train]InfoNCE contrastive · lr 5e-4 · NeighborLoader 10/5/3 ·
          batch 1 · temp 0.5 · num_neg 3 · early-stop on loss
-> [model]HG_l1000  = model/20260518_102121/global_fold_early_stop.pth (epoch 23)
-> [embs]phase1_drug_embeddings.npy (8981×256)  ≡ author reference

The model is a heterogeneous graph neural network — drug nodes, gene nodes, and three edge types. Training is contrastive: for each real edge, sample non-edges as negatives and pull positives together, push negatives apart (InfoNCE, temperature 0.5). Only drug-centered subgraphs are loaded (NeighborLoader), so each batch sees a slice of the graph. A single HeteroGNN weights the whole graph; the trained drug rows are saved as phase1_drug_embeddings.npy and equal the author's reference table (verified per hg/AGENTS.md).

Key fact: this stage never touches FDA drugs. It defines the embedding space on L1000-only molecules (indices 0–8980).

2. HG FDA extension: data + finetune (11,104 drugs)

2a. Collect FDA graph data

Sources: src/query_dti_fda.py, src/compute_dds_fda.py, src/infer_fda_hg.py.

[drugs]2,123 FDA SMILES
-> [query_dti_fda.py]ChEMBL API · pChEMBL≥6.0
        -> [edges]DTI_edge_index_fda_ext.npy (3,984 drug-gene)
+ [drugs]FDA Morgan fingerprints
-> [compute_dds_fda.py]Tanimoto>0.5106 · density-matched to train DDS
        -> [edges]DDS_edge_index_fda_drugs.npy (7,659 drug-drug)
+ [drugs]FDA KPGT embeddings (embeddings/all_drugs_idx2KPGT.npy)
-> [infer_fda_hg.py]Ridge regression KPGT→512
        -> [nodes]FDA drug node features (2,123×512)

FDA drugs enter the graph through three engineered inputs: real drug–target edges pulled from the ChEMBL API, structural-similarity edges from Morgan fingerprints, and 512-d node features regressed from KPGT embeddings.

2b. Finetune on the extended graph

Source: src/finetune_hg.py.

[model]HG_l1000
+ [graph]extended · 8,981 train + 2,123 FDA drug nodes · 19,392 gene nodes
+ [edges]train PPI/DTI/DDS + FDA DTI/DDS
-> [train]full-graph forward · InfoNCE ·
          DTI all edges + DDS 20K sampled + PPI 50K sampled ·
          lr 5e-5 · 50 epochs · guard: train_cosim ≥ 0.95 (check every 5 ep)
-> [embs]all_drugs_idx2HG.npy (11,104×256) · FDA/Train std ratio 1.000

Two design choices matter:

  • Low learning rate (5e-5) — so the 8,981 training-drug embeddings barely move (cosine similarity to the pretrain embeddings is monitored and early-stops the run if it drops below 0.95).
  • Norm mapping — after training, FDA-row norms are quantile-interpolated to match training-row norms, which is why the final std ratio is 1.000.

The workflow and the library differ only in who presses the button:

v0 — run it in the model dir

You ran python -m src.query_dti_fda …, compute_dds_fda, then python -m src.finetune_hg --update-xpert-embeddings --embeddings-output embeddings/all_drugs_idx2HG.npy inside drug_emb_model/hg/. The library wrote the table itself.

v1 — workflow step 02 owns it

Step 02_drug_embeddings/02_drug_embeddings.py calls the same finetune_hg with the workflow's output path, then verifies the 11,104-row table. HG never writes into the workflow on its own (ADR 0002).

3. XPert pretrain (L1000)

Sources: pert_model/xpert/pretrain/run.sh, pretrain/config/l1000.yaml, src/train.py, src/model_xpert.py.

[drugs]UniMol 3D feats (11,104×122×514)
+ [drugs]HG bio embeddings (11,104×256)     ← built by HG (sections 1–2)
+ [drugs]dose / time / cell tokens
+ [cells]binned expression (n_bins=128) + PPI gene vectors (978×128)
+ [data]l1000_mdmt_full_336852.h5ad
+ [model]XPert_untrained · dual-branch Transformer ~25M ·
          trt CA+SA+SA+CA · ctl SA+SA+SA+SA
-> [train]loss = 0.2·L_trt + 0.003·L_ctl + 0.2·L_deg + 1.0·L_pcc ·
          lr 0.004 · batch 64 · GradScaler · early-stop on PCC (patience 50)
-> [model]XPert_l1000 = pretrain/output/pretrain_mdmt_full_50_epoch.pth

XPert is a dual-branch transformer: one branch predicts the perturbed state (x_pert), one the control state (x_ctl), and the DEG output is the difference x_deg = x_pert − x_ctl. Drug features (UniMol 3D + HG biological) fuse with cell-state features (binned expression + PPI gene vectors) via cross-attention layers.

The loss is a weighted blend of four terms — perturbed-state MSE, control-state MSE, DEG MSE, and Pearson correlation on the DEG. The PCC term carries the full weight (1.0) and is also the early-stopping metric.

4. XPert finetune + FDA predict (DToxS) — v0 vs v1

The model training is identical; the orchestration is not. This is the central contrast of the lesson.

v0 · library-driven

[model]XPert_l1000
+ [data]finetune/data/dtoxs.h5ad
+ [feats]drug_embeddings/ (UniMol+HG)
-> bash finetune/run.sh <ckpt> dtoxs dtoxs \
        finetune/config/dtoxs
-> [train]4 ep · batch 32 · finetune_lr 0.002 ·
          init_epoch 0 · warm-start split → final
-> [model]finetune/output/dtoxs_warm/*_best.pth
-> bash predict/predict.sh --model_path dtoxs_warm \
        --ctl_csv cm_ctl_landmark.csv \
        --drug_csv fda_drugs.csv
-> [output]xpert_fda-cm_deg.csv

v1 · workflow step-wise

[model]XPert_l1000
+ [data]input/dtoxs.h5ad
+ [feats]input/* + 02_drug_embeddings/output/*  (via config)
-> 04_finetune_xpert.py   (dtoxs all-train,
                            4 ep · batch 32 · lr 0.002)
-> [model]04/output/dtoxs_dtoxs/
          dtoxs_dtoxs_fold-1_best.pth
-> 05_benchmark_xpert.py  (warm-start 10f ·
          cold-drug 10f · cold-cate 6f)
-> [eval]benchmark.csv + benchmark.png
-> 06_perturbed_transcriptome.py
-> [output]06/output/xpert_fda-cm_deg.csv
The v0→v1 diff in one sentence: v0 ran training/prediction ad-hoc from inside pert_model/xpert/ (scripts + notebooks), so the library owned the artifacts; v1 made XPert a pure library and moved finetune/benchmark/predict into numbered workflow steps that own their weights and CSVs (ADR 0002).

Three concrete consequences of that shift:

  • Final model differs. v0's DEG table came from a warm-start finetune; v1 step 04 uses the all-train dtoxs split (dtoxs_dtoxs_fold-1_best.pth). Benchmark folds (warm-start, cold-drug, cold-cate) moved to step 05.
  • Config root moved. v0 configs resolved against pert_model/xpert/; v1 configs resolve against the workflow (src/config.py root-aware paths), pointing PPI vectors back to the library but embeddings into workflow dirs.
  • Idempotence + parity. v1 steps skip if cached artifacts exist; retraining/predicting is GPU-fp-nondeterministic across environments, so re-running can break parity with archived CSVs (--force is explicit).
