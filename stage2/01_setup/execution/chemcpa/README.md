## Finding (2026-10-18)

Every checkpoint in the public zip is a raw `ComPert` state dict trained on the
**L1000 977-gene** space (or its 2,000-gene extension), with **188 drugs** and
**3 covariates**. None is a 5,000-gene or 20,570-gene model. The downloaded
`combo_sciplex` data is 5,000 genes, so a real chemical prediction on it is not
possible from these public weights without retraining.

The smoke therefore does the documented C2 fallback:

1. builds the exact `ComPert` architecture from the checkpoint's saved config;
2. loads the state dict strictly;
3. runs one forward pass on a synthetic L1000-shaped batch (8 cells, 977 genes,
   188 drug indices, 3 covariates);
4. saves `output/pred.npy` and `output/meta.json`.

Expected output: `output/meta.json`, `output/run.log`. The 2026-10-19 run also
wrote `output/pred.npy` (8 × 977); deleted in ticket 06, regenerated by a rerun.

**Result (2026-10-19 re-run):** passed. `27b401db...pt` loaded with **0 missing / 0
unexpected** tensors; forward produced **8 × 977**. The public state dicts have
no covariate-embedding tensors even though their config says `[3]`, so the smoke
builds the model with `num_covariates=[0]`; the run is therefore a pure
architecture/checkpoint check.

This proves checkpoint/architecture compatibility, **not** a biological
prediction. Any Stage 2 use of chemCPA at 5,000/20,570 genes requires retraining
or a different public checkpoint. `inspect_checkpoint.py` records the shape
inventory of all downloaded checkpoints.
